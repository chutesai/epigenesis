# C45: explicit per-run EDA backend

All 15 model-building modules in `experiments/end_to_end` now use a shared backend helper. `--eda-backend {naive_fp32,fla_kda_2t}` defaults to the existing naive kernel. The default is numerically identical; artifacts gain a field (assuming the external builder’s prior default is naive_fp32). Each CLI prints `EDA-BACKEND <name>`. FLA selection prepends `/workspace/malleable/pydeps_fla` when present and requires a callable `fla.ops.kda.chunk_kda` before calling the builder; import failures abort without fallback.

`eda_backend` is recorded in RESULT/FINAL JSON, saved patch metadata, comparison manifests, C42 feature caches/bank manifests, diagnostic outputs, base-cache manifests/keys, and C44 resume configuration hashes. Evaluators reject banks or feature caches from another backend; bank assembly and C38/C42 analysis reject mixed comparisons. Missing legacy fields mean `naive_fp32`. Diagnostic scripts and the new helper/tests/report are included in the repository allowlist.

Validation: 31 C45 CPU tests pass, covering fake-builder propagation, dependency failure, artifact persistence, cache separation, C44 resume rejection, mismatch refusal, mixed analysis rejection, and legacy defaults. The full end-to-end sweep produced 1,075 passes and one skip; its three C40 mock-signature failures were fixed and all three passed the recorded-failure rerun. C40 plus C45 pass 41 tests; a further decisive/C42 serving regression run passes 23 tests. Compilation and `git diff --check` pass. Real FLA kernels/GPU numerics were not exercised on this CPU host.
